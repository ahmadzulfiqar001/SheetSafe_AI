# Step 7J: transport-neutral synthetic validation

Scope: pure validation and in-memory preparation simulation, implemented on
2026-10-23 from checkpoint `38ec781`. The existing uncommitted Step 7I design and
discovery links are preserved. **The proposed PRD transport amendments are not
approved.** No stdin receiver, sealed-FD implementation, collector, freezer,
filesystem transport, Docker API, real upload or execution path is added.

## Modules and authority boundary

`runner/transport_protocol.py` defines frozen internal job/manifests, strict JSON,
incremental frame validation and quarantined output metadata. It imports no
backend/storage/runtime clients and performs no filesystem, socket or process I/O.
`runner/transport_state.py` exercises logical preparation through an injected
receive/close protocol, tested only with in-memory fakes and controlled clocks.

Server context and expected manifests must be created by trusted code, not by
copying a received ownership claim. Session/run IDs, UUIDs, digests and epochs
are not credentials. The standalone validator/simulator does not check persistent
ownership. Step 7K adds a separate [trusted SQLite integration](runner-durable-jobs.md)
for fixed synthetic jobs on existing runs, using existing ownership checks and
atomic fenced state. No parsed object, callback result or simulation receipt
grants permission to create a container.

The unchanged SandboxPolicy still uses stopped-container-archive, UID/GID 10001,
disabled execution and the same SEC01-SEC10 requirements. The image/bootstrap,
Docker adapter, preflight and host readiness modules are unchanged. Existing
LSM and execution gates remain effective. No API or frontend imports this code.

## Internal synthetic manifest version 1

Input JSON is a separate bounded metadata object; it is not a stdin protocol.
No transport for delivering it is supplied. Required fields, without extras:

| Field | Rule |
| --- | --- |
| protocol_version | Exact integer 1; booleans/floats/other versions rejected |
| fixture_id | Exactly smoke-v1 |
| job_id | UUID4 hex generated by JobBinding; cannot be supplied/replaced through ordinary constructor/dataclass operations |
| session_id, run_id | Trusted expected ASCII opaque bindings, 1-128 alphanumeric/underscore/hyphen characters |
| lease_epoch | Trusted expected exact integer 1 through 2^63-1; not proof that a lease exists |
| payload_length | Exact expected integer 1 through 262,144 bytes |
| sha256 | Exact expected canonical lowercase 64-hex digest |
| metadata | Exactly purpose=synthetic-transport-check; no arbitrary metadata, paths, commands or credentials |

`InputManifest.for_payload` hashes bounded immutable bytes in trusted test/server
code. Validation compares received fields to that expected manifest and returns
the existing trusted object, never a newly minted job. Field names are strict;
duplicate keys at any object depth, malformed UTF-8/JSON, floats, nonfinite
numbers, excessive integer encodings/depth, trailing JSON and unknown fields
fail with bounded sanitized error codes. Input metadata is <=4 KiB. Canonical
encoding sorts keys with compact ASCII JSON; arbitrary input JSON whitespace or
key order is not treated as a different job.

The 256 KiB single-payload profile is intentionally smaller than the conditional
Step 7I multi-object/dataset proposal. No parser/candidate/validator role, arbitrary
code field or dataset admission is enabled. Payload bytes are opaque and never
interpreted or executed, even when they contain code-like text or READY/GO words.
Increasing limits or adding roles/fixtures requires a separately reviewed version.
Unknown protocol versions fail closed; there is no legacy fallback.

## Framing and resource bounds

V1 data frame header is 61 bytes, network byte order:

| Bytes | Meaning |
| --- | --- |
| 4 | SSFT magic |
| 1 | Protocol version 1 |
| 16 | Server job UUID bytes |
| 32 | SHA-256 of canonical expected input manifest |
| 4 | Zero-based sequence, unsigned uint32 |
| 4 | Data byte count, unsigned uint32 |

Each full frame carries 64 KiB except the exact-sized final remainder. A payload
has 1-4 frames, <=256 KiB data, at most 256 KiB +244 bytes framed wire data. One
feed fragment is <=65,597 bytes (header plus one maximum body); callers must
split larger deliveries. Arbitrary fragmentation across header/payload boundaries
works; the validator does not assume a socket read equals one frame.

`FrameValidator.feed` checks header version/job/manifest binding, sequence and
declared body length before consuming its body. It hashes body slices directly
without retaining payload bytes; only a partial header (<=61 bytes) is buffered.
Cumulative checks explicitly compare remaining declared/global byte allowances.
Repeated/reordered frames, zero/oversized lengths, wrong identity, extra/trailing
bytes and mutable/non-bytes/empty feed chunks are rejected. An error poisons the
instance permanently and clears its header buffer; later feed/finish cannot
recover or consume more input.

Explicit `finish()` is required at complete-stream EOF. Merely reaching the
declared byte count is not success: final header/body completeness, exact total
length and independently computed SHA-256 must all match. Successful evidence
has execution_enabled=false. It proves byte/metadata agreement only, not sender
authentication, persistent authorization, input immutability or correctness.
The manifest-binding SHA-256 is unkeyed, not a MAC or authenticated channel.
This framing is transport-neutral, not Docker attach framing and not approval
to replace stopped archive preparation.

## Simulated preparation and recovery

Normal logical history:

```text
CREATED -> RECEIVING -> INPUT_VERIFIED -> READY_FOR_EXECUTION
```

READY_FOR_EXECUTION is a requested **logical test label only**. All receipts
keep execution_enabled, persistent_authorization_verified,
input_immutability_verified and cleanup_verified false, plus all ten SEC controls
UNVERIFIED. No create/start/exec/publish callback exists.

The simulator compares the expected manifest first, then feeds bounded reads
through the validator until explicit None EOF. Empty bytes are an invalid
fragment, not EOF. It rechecks injected cancellation/lease predicates around
each read and after stream close. Only exact True passes the fake lease check.
INPUT_VERIFIED can be followed by failure if ownership/cancellation/deadline or
close changes before readiness. A normal close return is recorded as just that,
not verified resource cleanup.

Fixed simulated budgets: 10 seconds total, <=1 second per receive, at most 4,096
read operations. Clocks must be finite and monotonic. A stream fragmented beyond
that operation cap fails rather than using an unlimited loop; it is separate
from the pure validator's byte bounds. Calls receive explicit max_bytes/timeout
arguments. The harness checks elapsed time after return but **cannot preempt a
blocking transport, clock, lease or cancellation callback**. A future real driver
needs interruptible deadline-bounded I/O and independent enforcement; none is
implemented here. Controlled clocks avoid sleeps in tests.

Terminal states are FAILED, INTERRUPTED, TIMED_OUT and CANCELLED. Malformed/hash/
identity failures stop reads, close is attempted once, and unexpected exception
text is not exposed. KeyboardInterrupt/SystemExit-style process interrupts are
not swallowed; the instance becomes interrupted and cannot restart. Cancellation
is modeled with a terminal receipt, not a promise of actual process teardown.

Each simulator is one-shot, with a nonblocking lock rejecting concurrent/reentrant
or repeated preparation. No reset/resume/retry method exists. Simulated retries
use a new job UUID and fresh validation; old frames fail binding checks. This
does not implement global/durable replay protection by itself. The Step 7K
integration supplies atomic claims and fenced stages for fixed synthetic jobs;
standalone simulators still lack that authority. New UUID/epoch construction alone cannot
authorize a retry or extend any real PRD attempt/time/retention budget.

## Output metadata rules, not collection

Trusted code issues frozen `ArtifactSlot` objects bound to the expected job.
IDs are server-generated 32-hex UUIDs; exact names are
`a_<artifact_id>.<csv|png|json|txt>`. Candidate-supplied names/IDs must match those
slots exactly; no path normalization or permissive case folding. Source-code
downloads from a trusted source registry are outside these candidate-output
slots; py/HTML/SVG/XLSX slots are not enabled here.

Output JSON <=16 KiB contains the same version/fixture/job/session/run/epoch
binding plus artifacts. Each entry has exactly artifact_id, filename, kind,
byte_count and sha256. Kind must claim regular; links/special-file declarations
and unknown fields are rejected. Every expected slot must appear exactly once.
Enforce <=10 artifacts, <=10 MiB each and <=20 MiB combined with strict integer
checks and subtraction-based remaining-capacity checks. Empty declared files are
metadata-valid, pending later format/safety checks. Duplicate slots/entries,
missing expected entries, foreign bindings, malformed digests and unsafe names
fail. Zero outputs are metadata-valid only when the expected slot set is empty.

Parsed results are explicitly **ArtifactClaim/OutputClaims**, status QUARANTINED,
content_verified=false, publication_allowed=false. A syntactically valid digest
is still a candidate claim. No actual file type, size, hash, symlink safety,
content format, numerical correctness or cleanup is attested by this parser.
Future independent collection must measure actual bytes/hash and metadata;
existing private quarantine storage and independent validation must precede any
publication. There is no host collector or means to promote these claims.
